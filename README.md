# Dota 2 duel solver — Pudge vs Invoker, patch 7.41f

Исследование оптимальных сборок и оптимальной игры в дуэли 1 на 1 методами
динамического программирования и поиска по игровому дереву.

**Статус: исследовательский проект, не готовый продукт.** Ниже честно описано,
что проверено, а что ещё нет — это важнее списка возможностей.

---

## Что это

Дуэль двух героев 15 уровня на пустой плоскости:

* арена — прямоугольник 30 × 80 м, выход за границу = поражение;
* сетка времени 250 мс, полушаг 125 мс (поочерёдные ходы);
* золото не ограничено, доступны все предметы, инвентарь — 6 слотов;
* без крипов, башен, рельефа и деревьев.

Цель — найти сборки и стратегии, оптимальные в равновесии, а не «средние по
мете».

## Структура

```
dota2sim/
  constants.py      формулы Dota: броня, магическое сопротивление, скорость,
                    скорость атаки, порядок операций
  herodata.py       Pudge 15 ур. из официального datafeed
  model.py          сущности: способности, предметы, бафы, типы урона
  forward.py        вперёд-модель: касты, снаряды, площадные эффекты,
                    каналы, призывы, туман войны, предметы
  build.py          сборка героев из данных, применение предметов
  test_forward.py   проверка механик против аналитики
  tactical.py       геометрия уклонения от скиллшотов

data/
  abilities_741f.py 10 способностей Invoker, параметризованы сферами
  items.py          37 предметов и 7 нейтральных
  *.md              источники и выписки по патчу

solvers/
  npdp.py           ДП по сетке (numpy), упорядоченный Гаусс–Зейдель
  matrixgame.py     цена матричной игры (одновременные ходы)
  dp.py             эталонная реализация ДП на чистом Python
  search.py         поиск по дереву: альфа-бета, итеративное углубление,
                    таблица транспозиций
  valuefn.py        функция ценности для листа
  train_value.py    обучение функции самопгрой
  evaluate.py       оценка позиций

docs/
  formulation.md          математическая постановка
  forward_architecture.md архитектура вперёд-модели и поиска
  ../results/STATUS.md    журнал: что проверено, какие баги найдены
```

## Что проверено

* **Механики вперёд-модели — 6 из 6 против аналитики:** автоатаки, Rot
  (скорость и размер импульса), самоурон Rot со снижением сопротивлением,
  частота проков Cold Snap, урон и время полёта хука, поражение за выход.
  Запуск: `python3 -m dota2sim.test_forward`.
* **Формулы сверены с официальным datafeed Valve** для патча 7.41f: HP, мана,
  броня, скорость атаки, урон — воспроизводятся точно.
* **Решатели сверены между собой:** numpy-ДП против эталона на чистом Python,
  параллельная версия против последовательной.
* **Поиск проверен на позициях с очевидным ответом** (4 из 4).
* **Функция ценности:** точность 0.81–0.84 на отложенной выборке, калибровка
  монотонна (предсказание 0.1 → факт 0.11, 0.5 → 0.52, 0.9 → 0.89).

## Что не проверено и чего нет

Это список известных ограничений, а не пожеланий:

* **Активы реализованы у 6 предметов из 37** (Blink, Scythe, Eul's, Orchid,
  Abyssal, Blade Mail); остальные дают только статы.
* **Пассивы предметов по большей части отсутствуют**: Heart, Skadi, Shiva's,
  Assault Cuirass, Satanic (лайфстил), Eternal Shroud, Mage Slayer, Aghanim's.
* **Расходники не реализованы вообще** (Magic Wand, Faerie Fire, Mango,
  Raindrops).
* **Нейтральные предметы не реализованы.**
* **Призывы нельзя атаковать**; уклонение и лайфстил считаются в статах, но в
  бою не применяются.
* **Функция ценности обучена на модели до последних исправлений** — её нужно
  переобучить.
* **Лужа/деревья/рельеф отсутствуют** — по условию задачи.

## Установка и запуск

```bash
pip install -r requirements.txt       # нужен только numpy

python3 -m dota2sim.test_forward      # проверка механик (6 проверок)
python3 -m solvers.train_value        # обучение функции ценности самопгрой
python3 -m solvers.evaluate --vf results/valuefn.npz
```

Файлы `results/*.npy` в репозиторий не входят (десятки мегабайт, регенерируются
прогонами). Поиск и оценку можно запускать без них, если не загружать
сохранённые функции ценности.

## Источники данных

Все числа привязаны к патчу **7.41f** (15 сентября 2026). Основной источник —
официальный datafeed Valve:

* `https://www.dota2.com/datafeed/herodata?hero_id=14` (Pudge)
* `https://www.dota2.com/datafeed/herodata?hero_id=74` (Invoker)
* `https://www.dota2.com/datafeed/itemlist` и `itemdata` (предметы)

**Важно:** `dota2.fandom.com` в момент сбора данных был заморожен на эпохе 7.35
и содержит неверные значения для всего, что изменилось в 7.40–7.41. Числа из
него не используются.

## Журнал

`results/STATUS.md` — история работы с перечнем найденных ошибок модели. Он
полезнее итоговых чисел: каждая ошибка давала правдоподобный, но вырожденный
ответ, и большинство из них были допущениями, вшитыми в конструкцию, а не
опечатками.
